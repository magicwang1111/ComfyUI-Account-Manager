# ComfyUI Account Manager 30实例全局调度使用文档

## 1. 功能说明

本方案在不修改 ComfyUI 核心代码的前提下，通过
`ComfyUI-Account-Manager` 管理多个 ComfyUI 实例的共享任务队列。

默认启动30个实例：

```text
8180、8181、8182……8209
```

用户可以从任意一个端口登录和提交任务。任务不会固定在入口端口执行，
而是由任意空闲 Worker 领取。浏览器仍通过原入口端口接收队列状态、
执行进度、预览和完成事件。

主要规则：

- 普通账户全局最多同时运行6个任务。
- 同一账户的第7个及后续任务保持排队。
- 其他账户不受该用户排队任务阻塞。
- 管理员默认不受任务并发数限制。
- 普通用户只能查看自己的队列、历史和资产。
- 管理员可以查看全部用户的任务、历史和资产。
- Worker 失联后，其运行任务标记为 `worker_lost`，不会自动重试。

## 2. 文件和数据说明

插件目录默认为：

```text
/mnt/ComfyUI/custom_nodes/ComfyUI-Account-Manager
```

重要文件：

| 文件 | 用途 |
| --- | --- |
| `config.json` | Account Manager 和调度器配置 |
| `users_db.json` | 全部实例共享的账户数据 |
| `secret_key.txt` | JWT签名密钥 |
| `scheduler_secret.txt` | Worker内部事件HMAC签名密钥 |
| `scheduler.sqlite3` | 共享任务队列、Worker心跳和全局资产索引 |
| `history.sqlite3` | 全局持久化任务历史 |
| `account_manager.log` | Account Manager日志 |

每个Worker还拥有独立的ComfyUI Assets数据库：

```text
/mnt/ComfyUI/user/comfyui-8180.db
/mnt/ComfyUI/user/comfyui-8181.db
……
/mnt/ComfyUI/user/comfyui-8209.db
```

不要让多个ComfyUI进程共同使用默认的 `user/comfyui.db`。SQLite不允许
多个ComfyUI实例同时持有该数据库的独占初始化锁。

## 3. 安装和升级

### 3.1 安装依赖

```bash
cd /mnt/ComfyUI
source /root/miniconda3/etc/profile.d/conda.sh
conda activate comfyui
pip install -r custom_nodes/ComfyUI-Account-Manager/requirements.txt
```

新增依赖中包含 `filelock`，用于保护账户文件的并发读写。

如果服务器上的Conda不在 `/root/miniconda3`，请使用实际的
`conda.sh` 路径。管理脚本也会尝试自动查找Conda。

### 3.2 更新代码

```bash
cd /mnt/ComfyUI/custom_nodes/ComfyUI-Account-Manager
git pull origin main
```

当前30实例调度版本对应提交：

```text
c8af54ba55c2954e02894fff1fdd50413a7a09fe
```

### 3.3 安装管理脚本

```bash
cp /mnt/ComfyUI/custom_nodes/ComfyUI-Account-Manager/manage_comfyui.sh \
   /mnt/Comfyui-admin/manage_comfyui.sh
chmod 750 /mnt/Comfyui-admin/manage_comfyui.sh
bash -n /mnt/Comfyui-admin/manage_comfyui.sh
```

`bash -n` 没有输出即表示Shell语法检查通过。

## 4. 配置说明

`config.json` 中与分布式调度相关的默认配置如下：

```json
{
  "distributed_queue_enabled": true,
  "scheduler_db": "scheduler.sqlite3",
  "max_concurrent_jobs_per_user": 6,
  "admin_concurrency_limit": 0,
  "worker_heartbeat_seconds": 5,
  "worker_stale_seconds": 60,
  "scheduler_secret_file": "scheduler_secret.txt"
}
```

参数含义：

| 参数 | 说明 |
| --- | --- |
| `distributed_queue_enabled` | 是否启用多实例共享队列 |
| `scheduler_db` | 共享调度数据库文件 |
| `max_concurrent_jobs_per_user` | 普通用户全局最大运行任务数 |
| `admin_concurrency_limit` | 管理员并发限制；`0` 表示不限 |
| `worker_heartbeat_seconds` | Worker写入心跳的间隔 |
| `worker_stale_seconds` | 超过该时间无心跳则视为失联 |
| `scheduler_secret_file` | 内部事件转发签名密钥文件 |

全部Worker必须：

- 使用同一个Account Manager插件目录。
- 共享 `users_db.json`、JWT密钥、调度密钥和调度数据库。
- 设置正确的 `ACCOUNT_MANAGER_INSTANCE_PORT`。
- 使用各自独立的 `comfyui-端口.db`。
- 使用同一个ComfyUI输入、临时和输出目录。

首次启动时会自动创建调度数据库和调度密钥。不要为不同Worker复制出
不同内容的 `scheduler_secret.txt`，否则跨端口事件转发会被拒绝。

## 5. Linux服务器启动30个实例

进入管理目录：

```bash
cd /mnt/Comfyui-admin
```

默认配置已经是30个实例，因此可以直接执行：

```bash
./manage_comfyui.sh restart
```

也可以显式指定实例数：

```bash
INSTANCE_COUNT=30 ./manage_comfyui.sh restart
```

端口范围计算方式：

```text
起始端口8180 + 30个实例 = 8180–8209
```

原有的8180–8190仍然会启动，新增的是8191–8209。

### 5.1 常用管理命令

启动全部实例：

```bash
./manage_comfyui.sh start
```

停止全部实例：

```bash
./manage_comfyui.sh stop
```

重启全部实例：

```bash
./manage_comfyui.sh restart
```

查看全部实例状态：

```bash
./manage_comfyui.sh status
```

只操作指定端口：

```bash
./manage_comfyui.sh restart 8188
./manage_comfyui.sh stop 8209
./manage_comfyui.sh start 8209
```

同时操作多个实例：

```bash
./manage_comfyui.sh restart 8180 8181 8182
```

查看指定实例最近日志：

```bash
./manage_comfyui.sh logs 8188
```

进入指定实例的tmux终端：

```bash
./manage_comfyui.sh attach 8188
```

退出tmux但不停止任务：

```text
先按 Ctrl+B，再按 D
```

### 5.2 自定义启动范围

例如从端口9000启动5个实例：

```bash
START_PORT=9000 INSTANCE_COUNT=5 ./manage_comfyui.sh restart
```

如需指定ComfyUI目录或Conda环境：

```bash
APP_DIR=/mnt/ComfyUI \
CONDA_ENV=comfyui \
START_PORT=8180 \
INSTANCE_COUNT=30 \
./manage_comfyui.sh restart
```

## 6. Windows本地双实例测试

`manage_comfyui.sh` 面向Linux服务器。Windows本地测试时，需要分别打开
两个PowerShell窗口。

先关闭正在占用默认数据库的旧ComfyUI进程，随后分别启动两个实例。

### 6.1 启动8188

```powershell
cd D:\ComfyUI
conda activate comfyui
$env:ACCOUNT_MANAGER_INSTANCE_PORT = "8188"
python main.py --port 8188 --enable-assets `
  --database-url "sqlite:///D:/ComfyUI/user/comfyui-8188.db"
```

### 6.2 启动8189

```powershell
cd D:\ComfyUI
conda activate comfyui
$env:ACCOUNT_MANAGER_INSTANCE_PORT = "8189"
python main.py --port 8189 --enable-assets `
  --database-url "sqlite:///D:/ComfyUI/user/comfyui-8189.db"
```

PowerShell中的反引号表示命令续行，也可以把命令写在同一行。

下面这条命令仅适用于单实例：

```powershell
python main.py --enable-assets
```

它使用默认端口8188和默认数据库
`D:\ComfyUI\user\comfyui.db`。如果另一个ComfyUI进程已经占用该数据库，
会出现：

```text
Could not acquire lock on database
```

多实例测试时必须为每个进程同时指定独立端口和独立数据库。

## 7. 账户使用

### 7.1 首个管理员

全新安装且账户库为空时，打开任意端口的 `/register` 页面创建首个账户。
首个账户会成为管理员。

后续账户只能由管理员创建。所有Worker共享 `users_db.json`，新账户注册
成功后不需要重启30个实例。

### 7.2 登录

用户可以访问任意公开入口，例如：

```text
http://服务器地址:8180/login
http://服务器地址:8188/login
http://服务器地址:8209/login
```

账户不绑定端口。同一账户在不同入口登录时，仍然看到自己的全局任务、
历史和资产。

### 7.3 API登录

```bash
curl -X POST "http://服务器地址:8180/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "username=用户名" \
  --data-urlencode "password=密码"
```

成功响应包含：

```json
{
  "message": "Login successful",
  "jwt_token": "JWT令牌",
  "user_settings_id": "用户ID"
}
```

后续API请求可以使用Cookie，也可以使用Bearer Token：

```bash
curl "http://服务器地址:8180/queue" \
  -H "Authorization: Bearer JWT令牌"
```

提交标准ComfyUI API工作流：

```bash
curl -X POST "http://服务器地址:8180/prompt" \
  -H "Authorization: Bearer JWT令牌" \
  -H "Content-Type: application/json" \
  --data-binary @prompt.json
```

`prompt.json` 继续使用ComfyUI标准API格式，不需要增加Worker端口字段。

## 8. 批量注册用户

批量注册脚本位于：

```text
/mnt/ComfyUI/custom_nodes/ComfyUI-Account-Manager/admin/bulk_register_sentinel.py
```

CSV文件格式：

```csv
username,password
user01,password01
user02,password02
```

管理员账号和密码通过环境变量提供，不要写入仓库：

```bash
cd /mnt/ComfyUI/custom_nodes/ComfyUI-Account-Manager
export COMFYUI_BASE_URL="http://127.0.0.1:8180"
export COMFYUI_ADMIN_USER="管理员用户名"
export COMFYUI_ADMIN_PASS="管理员密码"
export COMFYUI_USERS_CSV="/mnt/Comfyui-admin/users.csv"
export COMFYUI_REGISTER_RESULTS="/mnt/Comfyui-admin/register_results.csv"
python admin/bulk_register_sentinel.py
```

脚本仍然顺序调用8180的 `/register`，但注册结果会立即被全部Worker读取。

建议执行完成后清除当前Shell中的敏感环境变量：

```bash
unset COMFYUI_ADMIN_USER COMFYUI_ADMIN_PASS
```

如需长期保存凭据，应放在仅服务器管理员可读的配置中并设置：

```bash
chmod 600 凭据文件
```

## 9. 队列、历史、中断和资产

### 9.1 队列

```bash
curl "http://服务器地址:8180/queue" \
  -H "Authorization: Bearer JWT令牌"
```

普通用户看到自己在全部Worker上的排队和运行任务；管理员看到全部任务。

### 9.2 历史

```bash
curl "http://服务器地址:8180/history" \
  -H "Authorization: Bearer JWT令牌"
```

历史来自共享持久化数据库，重启Worker后仍然可以读取。

### 9.3 定向中断

```bash
curl -X POST "http://服务器地址:8180/interrupt" \
  -H "Authorization: Bearer JWT令牌" \
  -H "Content-Type: application/json" \
  -d '{"prompt_id":"需要中断的任务ID"}'
```

入口实例会根据 `prompt_id` 将中断请求路由到实际执行Worker。

普通用户不能中断其他用户的任务。普通用户发送不带 `prompt_id` 的中断
请求时，只影响自己的运行任务；管理员可以影响全部任务。

### 9.4 资产

```bash
curl "http://服务器地址:8180/api/assets" \
  -H "Authorization: Bearer JWT令牌"
```

入口会聚合存活Worker的资产，并通过全局索引路由资产详情、内容和删除
操作。普通用户只能看到自己的资产，管理员可以查看全部资产。

## 11. 上线验证

### 11.1 检查进程状态

```bash
cd /mnt/Comfyui-admin
./manage_comfyui.sh status
```

应显示30个 `running` 实例和8180–8209端口。

### 11.2 检查监听端口

```bash
ss -ltnp | grep -E ':(818[0-9]|819[0-9]|820[0-9])\b'
```

还需要确认云服务器安全组、防火墙、容器端口映射或反向代理允许访问
8180–8209。

### 11.3 检查Worker心跳

```bash
cd /mnt/ComfyUI/custom_nodes/ComfyUI-Account-Manager
sqlite3 scheduler.sqlite3 "
SELECT port,
       pid,
       active_prompt_id,
       datetime(last_heartbeat, 'unixepoch', 'localtime') AS heartbeat
FROM scheduler_workers
ORDER BY port;
"
```

正常情况下应看到30个端口，心跳时间持续更新。

### 11.4 检查任务状态

```bash
sqlite3 scheduler.sqlite3 "
SELECT status, COUNT(*) AS jobs
FROM scheduler_jobs
GROUP BY status
ORDER BY status;
"
```

检查各用户当前运行数：

```bash
sqlite3 scheduler.sqlite3 "
SELECT owner_id, COUNT(*) AS running_jobs
FROM scheduler_jobs
WHERE status = 'running'
GROUP BY owner_id
ORDER BY running_jobs DESC;
"
```

普通用户的 `running_jobs` 不应超过6。

## 12. 常见问题

### 12.1 `Could not acquire lock on database`

原因：多个ComfyUI进程使用了同一个 `comfyui.db`。

检查进程参数：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -match '^python' -and $_.CommandLine -match 'main\.py' } |
  Select-Object ProcessId, CommandLine
```

解决方法：停止错误实例，并为每个进程配置独立数据库：

```text
8188 → sqlite:///D:/ComfyUI/user/comfyui-8188.db
8189 → sqlite:///D:/ComfyUI/user/comfyui-8189.db
```

不要通过删除 `comfyui.db` 解决锁冲突。

### 12.2 第7个任务一直排队

这是普通用户并发限制的正常行为。检查该用户是否已经有6个
`running` 任务。任意一个任务完成、失败或取消后，第7个任务会自动被
空闲Worker领取。

### 12.3 任务显示 `worker_lost`

表示执行该任务的Worker超过60秒没有心跳。为了避免外部API重复调用和
重复扣费，该任务不会自动重试。

处理步骤：

1. 查看该端口日志。
2. 确认进程、机器资源和网络状态。
3. 修复并重启该Worker。
4. 由用户确认后重新提交原任务。

### 12.4 原入口收不到WebSocket进度

检查：

- 所有Worker是否共享同一个 `scheduler.sqlite3`。
- 所有Worker是否共享同一个 `scheduler_secret.txt`。
- `ACCOUNT_MANAGER_INSTANCE_PORT` 是否与实际监听端口一致。
- Worker之间能否通过实际端口互相访问。
- 任务提交JSON中是否包含稳定的 `client_id`。

### 12.5 Assets无法启动

每个实例必须同时具备：

```text
--enable-assets
--database-url sqlite:///独立数据库路径
```

并确认ComfyUI依赖已经安装：

```bash
cd /mnt/ComfyUI
pip install -r requirements.txt
```

### 12.6 `Cannot connect to comfyregistry`

这是ComfyUI-Manager访问远程节点列表失败，与共享调度数据库无关。
如果日志随后显示已经切换到本地列表，通常不会影响ComfyUI任务执行。

## 13. 安全建议

- 不要将管理员密码写进Python脚本、Shell脚本或Git仓库。
- `secret_key.txt` 和 `scheduler_secret.txt` 应仅允许服务账户读取。
- 对外服务建议使用HTTPS反向代理。
- 只开放业务需要的端口，并配置云安全组和系统防火墙。
- 不要向外部用户公开插件目录、SQLite数据库或内部密钥文件。
- 定期备份账户库、历史库、调度库和各端口Assets数据库。
- 修改并发限制后应统一重启全部Worker，确保行为一致。

## 14. 双GPU与API任务分池

Account Manager可以在统一入队入口扫描API prompt中的 `class_type`，不需要
修改任何业务节点。命中 `gpu_node_types` 中任意节点的工作流归入 `gpu`
池，其余工作流归入 `api` 池；混合工作流统一按GPU任务处理。

建议的双5090配置：

```json
"resource_concurrency_limits": {
  "gpu": 2,
  "api": 5
},
"gpu_node_types": [
  "CheckpointLoader",
  "CheckpointLoaderSimple",
  "UNETLoader",
  "KSampler",
  "KSamplerAdvanced",
  "SamplerCustom",
  "SamplerCustomAdvanced",
  "MiniMaxH3TurboLoRA",
  "MiniMaxH3TurboSampler",
  "SpectrumApplyMiniMaxH3"
]
```

`resource_concurrency_limits` 是单用户上限。实际全局并发仍由存活Worker
数量自动收紧。当前配置是2个GPU Worker和40个API Worker，分别最多同时
执行2个GPU任务和40个API任务；每个普通用户最多同时执行5个API任务。

42实例、6006起始端口的启动方式：

```bash
cd /root/autodl-tmp/Comfyui-admin
APP_DIR=/root/autodl-tmp/ComfyUI \
START_PORT=6006 \
INSTANCE_COUNT=42 \
GPU_COUNT=2 \
GPU_WORKER_COUNT=2 \
GPU_WORKER_INDICES=1,3 \
./manage_comfyui.sh restart all
```

端口分配结果：

- `6006`：`gpu` Worker，`CUDA_VISIBLE_DEVICES=0`。
- `6008`：`gpu` Worker，`CUDA_VISIBLE_DEVICES=1`。
- `6007`、`6009` 至 `6047`：`api` Worker，使用 `--cpu` 且不暴露GPU。

不要继续使用“11个实例对两张GPU轮询绑定”的旧脚本，否则同一张卡可能
同时运行多个本地MiniMax任务。升级时旧 `scheduler.sqlite3` 会原地增加
资源字段，尚未执行的旧排队任务会根据保存的prompt自动重新分类。

## 15. 回滚

如果30实例验收失败：

1. 停止全部30实例。
2. 保存 `scheduler.sqlite3` 和日志用于排查。
3. 恢复备份的Account Manager插件目录。
4. 恢复原管理脚本。
5. 按原来的11实例范围启动8180–8190。

```bash
cd /mnt/Comfyui-admin
INSTANCE_COUNT=30 ./manage_comfyui.sh stop
INSTANCE_COUNT=11 ./manage_comfyui.sh start
```

新增的 `scheduler.sqlite3` 不会覆盖原有的ComfyUI Assets数据库，可保留
用于故障诊断。
